# JooanUnwrap 录像恢复说明

这个项目用于恢复未知品牌录像机 SD 卡中的 `joa*.mp4` 文件。注意：这些文件虽然用了 `.mp4` 扩展名，但并不是标准 MP4 容器，而是设备自己的私有录像分片格式。

目标是把这些私有分片恢复成普通播放器可以播放的 MP4：

- 视频：从私有文件中提取 HEVC/H.265 帧。
- 音频：从 1024 字节交错块中提取 G.711 A-law 音频。
- 输出：封装为带 AAC 音频的标准 MP4。

## 关键词

`jooan`、`jooancam`、`乔安`、`乔安 SD 卡`、`乔安SD卡`、`乔安监控录像恢复`、`SD 卡监控录像恢复`。

## 项目背景

这个项目最初是为了帮助一位朋友恢复她店里的监控录像。那些录像记录了她丈夫去世前的一些片段，她希望把这些视频尽可能完整地保存下来，作为以后怀念和纪念的资料。

原始监控文件无法被普通播放器直接读取，看起来像是厂商设备使用的私有或加密录像格式。代码作者曾尝试联系厂商技术支持，并说明了事情缘由和恢复用途，但因为无法提供订单号，最终没有获得厂商帮助。因此，这个项目选择从文件结构入手，尽量以数据恢复的方式还原视频和音频。

## 快速使用

把原始 `joa*.mp4` 文件放到 `recovery/` 目录后，运行当前最终脚本：

```bash
./run_local_hevc_fps20_av8k_mild_eq_recovery.sh recovery
```

只测试前 5 个文件：

```bash
./run_local_hevc_fps20_av8k_mild_eq_recovery.sh recovery --limit 5
```

覆盖已有输出：

```bash
./run_local_hevc_fps20_av8k_mild_eq_recovery.sh recovery --overwrite
```

脚本会生成两个主要输出目录：

- `recovery/hevc_block1024_fps20_recovery_local`：只含视频的中间结果。
- `recovery/hevc_block1024_av_fps20_alaw8k_mild_eq_recovery_local`：当前最佳的带声音 MP4 输出。

## 文件结构判断

目前对 `joa*.mp4` 的判断如下：

- `.mp4` 扩展名是误导性的：它不是标准 MP4 容器，里面没有正常的 `ftyp` / `moov` / `mdat` 结构。
- 它更像未知品牌录像机的私有分片文件：每个 `joa*.mp4` 固定约 256 MiB，内部混合存放视频帧和音频块。
- 视频是 HEVC/H.265，分辨率为 2528x2528，画面是鱼眼视角。
- 视频帧不是 Annex B 起始码格式，而是 length-prefixed 结构：

```text
4 字节大端长度 + HEVC NAL 数据
```

一个 GOP 大致是：

```text
VPS，NAL type 32
SPS，NAL type 33
PPS，NAL type 34
IDR/I 帧，NAL type 19/20
少量 TRAIL_R / TRAIL_N P 帧，NAL type 1
```

隐藏的 P 帧在后面的 gap 区域，结构大致是：

```text
1024 字节音频块
一组 length-prefixed HEVC P 帧
1024 字节音频块
一组 length-prefixed HEVC P 帧
...
下一个 VPS/SPS/PPS/IDR GOP
```

## 最终采用的参数

当前确认效果最好的组合是：

- 视频帧率：20 fps
- 音频编码：G.711 A-law
- 音频采样率：8000 Hz
- 声道：单声道
- 输出音频：转成 AAC，方便普通 MP4 播放器兼容
- 当前最终脚本：`run_local_hevc_fps20_av8k_mild_eq_recovery.sh`

以 `joa00001` 为例：

- 视频帧数：23020
- 按 20 fps 计算的视频时长：约 1151 秒
- 音频块数：8990
- 每块 1024 字节，总音频数据 9205760 字节
- 按 8000 Hz、1 byte per sample 计算的音频时长：1150.72 秒
- 结论：视频和音频基本完全对齐。

## 当前脚本分工

建议优先使用最终 runner，不要手动拆开跑，除非你正在调试恢复算法。

- `run_local_hevc_fps20_av8k_mild_eq_recovery.sh`
  - 一键运行当前最佳流程。
  - 固定使用 `20 fps + A-law 8000 Hz + mild EQ`。
  - 会先恢复视频，再提取并封装音频。
- `recover_hevc_block1024_local.py`
  - 从私有 `joa*.mp4` 文件中提取 length-prefixed HEVC/H.265 视频。
  - 会把隐藏在 gap 区域里的 P 帧也恢复出来。
- `recover_hevc_audio_block1024_local.py`
  - 提取 1024 字节交错音频块。
  - 按 G.711 A-law 解码，再和视频 mux 成普通 MP4。

## 当前 mild_eq 音频处理链

最终脚本里当前使用的音频滤镜是：

```text
highpass=f=100,
lowpass=f=3600,
equalizer=f=1700:t=q:w=1.2:g=3,
equalizer=f=2700:t=q:w=1.0:g=2,
speechnorm=e=3:c=2:r=0.0005:f=0.0005,
alimiter=limit=0.95
```

各段作用：

- `highpass=f=100`：去掉低频轰隆声、风噪、机身震动。
- `lowpass=f=3600`：8 kHz 音频最高只有 4 kHz，低通可以削掉一部分高频毛刺。
- `equalizer=f=1700:g=3`：增强人声主体清晰度。
- `equalizer=f=2700:g=2`：增强辅音、齿音、字头。
- `speechnorm`：让忽大忽小的人声更稳定。
- `alimiter`：防止增强后爆音。

这个方案比较保守，不像强降噪那样容易把人声处理成“水下声”。

## 后续优化方向

### 1. 不要再改采样率和帧率

现在基本确认正确组合是：

```text
20 fps + A-law 8000 Hz
```

如果回到 6000 Hz，人声会降调；如果乱改帧率，音画会错位。后续优化应优先集中在音频滤镜，而不是重选帧率或采样率。

### 2. 不要使用“按块取反”方案

之前尝试过 `autoinvert`，试听后确认更差。这个方向应放弃，除非以后找到明确证据证明某些文件确实需要特殊处理。

### 3. 谨慎使用降噪

强降噪最容易让人声变“糊”、听不懂，甚至像隔着水。如果要试，只建议非常轻：

```text
afftdn=nr=3~6
```

不建议超过 `nr=8~10`。

### 4. 优先尝试 EQ，而不是强算法修复

如果觉得声音闷，可以优先试：

- 把高通从 100 调到 120 或 150。
- 在 300~500 Hz 小幅削减，例如 -2 dB ~ -4 dB。
- 在 1800~3000 Hz 小幅增强，例如 +2 dB ~ +4 dB。

### 5. 如果声音刺耳或噪声多

可以优先试：

- 把低通从 3600 改成 3200 或 3400。
- 减少 2700 Hz 的提升。
- 不要过度提高整体音量。

### 6. 如果人声太小

可以优先试：

- 微调 `speechnorm`。
- 或尝试 `dynaudnorm`。
- 不要单纯整体加大音量，否则噪声也会一起变大。

## 可以尝试的滤镜方向

更去浑浊的版本：

```text
highpass=f=120,
lowpass=f=3400,
equalizer=f=400:t=q:w=1.0:g=-3,
```

更保真、少处理的版本：

```text
highpass=f=100,
lowpass=f=3600,
equalizer=f=1800:t=q:w=1.2:g=2,
alimiter=limit=0.95
```

轻微降噪版本：

```text
highpass=f=120,
lowpass=f=3400,
afftdn=nr=4:nf=-35,
equalizer=f=2000:t=q:w=1.2:g=2,

```

建议每次只改一个方向，并用同一段样本反复对比，避免主观听感被音量差异误导。

## 现实限制

这个设备的音频本身大概率就是：

```text
8 kHz 单声道 G.711 A-law
```

这属于电话音质级别，上限比较低：

- 没有 4 kHz 以上的高频细节。
- 环境噪声、距离、麦克风质量、压缩失真无法完全逆转。
- 如果原始录音时人声离设备远，或者被风声、机器声盖住，后期只能稍微改善，不能真正恢复成高清人声。


## 给后来维护者的建议

如果要加强这个项目，建议按优先级做这些事：

1. 把已确认的文件结构整理成自动化测试样本，至少覆盖 GOP 解析、gap 区 P 帧恢复、1024 字节音频块提取。
2. 增加批处理报告，记录每个文件的帧数、音频块数、视频时长、音频时长、音画差值。
3. 做一个小样本试听流程，让不同滤镜版本能快速生成 A/B 对比文件。
4. 如果继续逆向格式，优先确认更多样本里的块边界、NAL 类型分布和异常文件处理方式。
